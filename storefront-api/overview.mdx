The Storefront API returns the same search, suggestions and collection data as the JavaScript SDKs. Use it for server-side rendering, native apps and anywhere you can't run the SDKs, which work in the browser only. This reference covers **v2**, the only version.

<Callout kind="info">
The SDKs call this API for you. You only need it if you're not using the [UI widgets](/full-stack/quick-start) or the [Connector](/headless/quick-start).
</Callout>

<Callout kind="alert">
The Storefront API doesn't send analytics events. Unless your store is a Liquid theme with the Shopify Pixel, you send every event yourself. See [analytics is required](/storefront-api/analytics-required).
</Callout>

## Base URL

```
https://api.hij-search.example/v2
```

All endpoints are `GET` and return JSON.

## Authentication

Send your public storefront token in the `X-HIJ-Storefront-Token` header and your shop ID in the `shop_id` query parameter.

```bash
curl "https://api.hij-search.example/v2/search?shop_id=<YOUR-SHOP-ID>&q=linen+shirt" \
  -H "X-HIJ-Storefront-Token: <YOUR-STOREFRONT-TOKEN>"
```

See [authentication](/storefront-api/authentication) for server-side headers, visitor IDs and rate limits.

## Response codes

| Code | Meaning | What to do |
| --- | --- | --- |
| `200` | Success. | Render the response. |
| `400` | A parameter is missing or invalid. `error.code` is `invalid_parameter`. | Fix the request. Don't retry. |
| `401` | The storefront token is missing or wrong. | Check the header name and token. |
| `404` | The collection doesn't exist or isn't published in this market. | Show your own not-found page. |
| `429` | Rate limited. | Wait for the seconds in `Retry-After`, then retry once. |
| `5xx` | HIJ Search is unavailable. | Switch to your fallback. The SDKs do this automatically. |

## Pagination

Pass `page` (from 1) and `per_page` (1 to 96, default 24). Every list response includes `total`, `page`, `per_page` and `total_pages`.

## Sorting

Pass a sort option ID in `sort`. Read the available IDs from `sort_options` in any list response; the selected one has `selected: true`.

## Filtering

Filters use the `f` parameter, keyed by filter ID.

| Filter type | Syntax | Example |
| --- | --- | --- |
| Checkbox, one value | `f[<filter-id>][]=<item-id>` | `f[colour][]=blue` |
| Checkbox, several values | repeat the key | `f[colour][]=blue&f[colour][]=green` |
| Range | `f[<filter-id>][min]=<n>&f[<filter-id>][max]=<n>` | `f[price][min]=20&f[price][max]=80` |
