HIJ learns from shopper behaviour. Searches, clicks, product views, add to cart and orders drive ranking, personalisation, merchandising reports and [A/B test](/ab-testing/overview) results. Every integration path needs analytics; what changes is who sends each event.

## Events

| Event | When | Group |
| --- | --- | --- |
| `search_performed` | A results page is shown for a query | Search and widget |
| `suggestion_selected` | The shopper picks a query or product suggestion | Search and widget |
| `product_clicked` | The shopper clicks a product in search results, a collection or a recommendation strip | Search and widget |
| `recommendation_viewed` | A recommendation strip is shown | Search and widget |
| `collection_viewed` | A collection page is shown (page 1) | Store |
| `product_viewed` | A product page is shown | Store |
| `product_added_to_cart` | A product is added to the cart | Store |
| `checkout_started` | The shopper starts checkout | Store |
| `order_completed` | An order is placed | Store |

Event fields are listed on the [Analytics API](/analytics/analytics-api#event-types) page. Every method sends the same event set.

## Who sends what

| Your store and path | Search and widget events | Store events |
| --- | --- | --- |
| Liquid theme + full stack or headless SDK | The SDK, automatically | [Shopify Pixel](/analytics/shopify-pixel), automatically |
| Liquid theme + Storefront API | You, with the [Analytics API](/analytics/analytics-api) | [Shopify Pixel](/analytics/shopify-pixel), automatically |
| Hydrogen or custom front end + SDK | The SDK, automatically | You, with [SDK manual analytics](/analytics/sdk-manual) or the [GTM template](/analytics/gtm/setup) |
| Hydrogen or custom front end + Storefront API | You, with the [Analytics API](/analytics/analytics-api) | You, with the [Analytics API](/analytics/analytics-api) |
| Native app or backend | You, with the [Analytics API](/analytics/analytics-api) | You, with the [Analytics API](/analytics/analytics-api) |

### How do I send analytics from a headless store?

If your headless store loads a JS SDK in the browser, the SDK already sends search, suggestion and collection events. Send product views, add to cart, checkout and orders with `HIJ.Analytics.track()` ([SDK manual analytics](/analytics/sdk-manual)), or with the [GTM template](/analytics/gtm/setup) if you already push ecommerce events to a data layer. If your headless store calls the Storefront API without an SDK, send every event with the [Analytics API](/analytics/analytics-api), from the browser or your server.

## Avoid duplicate events

Send each event from one place only. Duplicates inflate conversion rates and skew ranking.

| Combination | Rule |
| --- | --- |
| Shopify Pixel + SDK on a Liquid store | Don't call `HIJ.Analytics.track()` for product views, add to cart or checkout. The Collections connector detects the Pixel and skips its own `collection_viewed`. |
| Shopify Pixel + GTM template | Don't add GTM triggers for `view_item`, `view_item_list`, `add_to_cart` or `purchase`. |
| SDK manual analytics + GTM template | Pick one per event. Use `track: false` in the SDK if GTM sends everything. |
| Analytics API from the server + the browser | Send `order_completed` from your order webhook only, not also from the thank-you page. |

## Consent

Every method respects the shopper's analytics consent:

| Method | Consent source |
| --- | --- |
| Shopify Pixel | Shopify's Customer Privacy API (your cookie banner) |
| JS SDKs | `analyticsConsentProvided()` in the [full stack](/full-stack/quick-start#analytics-and-consent) or [headless](/headless/quick-start#analytics-and-consent) configuration |
| GTM template | The `consentMode` field |
| Analytics API | You. Send events, visitor IDs and session IDs only after consent. |
